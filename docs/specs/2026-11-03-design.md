# orca-box design (2026-11-03)

## Goal

One dedicated home box runs the Orca server so agents (Claude Code, Codex, Antigravity) keep working while the Mac sleeps or travels. Setting up a box, moving to a new one and retiring the old one should each be a short, repeatable procedure.

## Decisions

- **Box:** Ubuntu Server 24.04, amd64 or arm64. Orca runs as a systemd user service for a non-root user with linger; the admin user keeps sudo.
- **Reach:** Tailscale with Tailnet Lock; Orca's own transport is plain `ws://`, so it travels only inside the tailnet or the LAN. No router port forwarding. The Orca port also stays open to the LAN as a fallback.
- **Firewall:** ufw default deny incoming; allow SSH, everything on `tailscale0`, and the Orca port from the LAN /24.
- **Manual on purpose:** Tailscale login, signing the node under Tailnet Lock, disabling its key expiry, agent logins, GitHub token, Orca pairing. Each needs the owner's account or produces a credential.
- **What moves between boxes:** code through git; agent memory and history through `backup.sh`/`restore.sh`; logins and pairing are redone rather than copied. Orca automations are recreated by hand (their storage was not verified).
- **Where things live:** procedure and scripts in this repo; lessons and test results in the owner's wiki.

## Known limits

- `setup-box.sh` pins the Orca and Codex versions; the installers it calls can change between uses. Rerun on a real box before trusting it.
- The service restart ends running agents; a reboot does too.
- Claude memory is keyed by repo path, so repos must be cloned to the same paths after a move.
